# 竞品分析报告模板（详细规范）

> 本文件是 `competitive-analysis-report` 技能的正文规范。执行时严格按此产出。

## 0. 输入参数

唯一参数 `TOPIC`，两类输入：

- **具体单品**（如"剪映 PC 版"）：以该产品为核心对标主体，全网检索同赛道直接竞品、间接竞品、潜在竞品，做定向对标。
- **产品品类**（如"AI 视频生成产品""律师事务所官网"）：自动筛选赛道 TOP 头部竞品与梯队玩家，做品类全景格局分析。

适配全行业 ToB/ToC、工具类、AI 类、软硬件、数字化服务。纯竞品导向，聚焦对标、格局、差异化优劣、市场攻防、机会缺口。

## 1. 三阶段执行

严格按「信息检索收集 → 信息清洗结构化 → 正式报告撰写」执行，不跳步、不编造数据，数据优先用近 2-3 年（2024 至今）公开来源。

### 阶段 1 检索收集
- 自动生成多组差异化关键词，覆盖：竞品清单、梯队、功能、产品形态、定价、盈利模式、渠道、目标用户、技术壁垒、用户口碑、优劣势、迭代动态、市场份额/渗透率、落地场景、运营营销打法、政策合规、用户痛点差评、行业横评、差异化亮点、潜在入局者、风险与机遇。
- 来源多元：产品官网、权威测评、行业白皮书、券商研报、科技媒体、用户社区/论坛。
- 信息分层标记：客观事实 / 测评观点 / 用户口碑 / 网络传闻；标注时效；旧数据只作历史溯源。

### 阶段 2 清洗结构化
- 去重、删无效与过期信息；多来源冲突数据标注口径差异与来源。
- 按报告框架归档：赛道全景、梯队、头部拆解、横向对标、SWOT、口碑差异、打法策略、缺口、风险机会。
- 萃取关键数据、核心优劣势、痛点、空白机会、竞品短板。

### 阶段 3 撰写正式报告
文风专业严谨、对比式表述、术语辅以通俗解释；多口径冲突数据标注来源与口径。

## 2. 固定目录（12 节）

1. 竞品调研摘要（核心竞争结论、调研范围、核心发现、机会与风险浓缩）
2. 调研概述（背景、对标维度、方法、数据时效、适配场景）
3. 赛道整体竞争格局
   - 3.1 现状与市场集中度
   - 3.2 梯队分层（头部 / 腰部 / 长尾 / 潜在入局者）
   - 3.3 核心竞争特征与行业趋势
4. 核心竞品基础信息深度拆解
   - 4.1 定位、核心赛道、目标人群
   - 4.2 发展历程、当前迭代阶段、市场布局
   - 4.3 核心技术壁垒、主打优势
5. 多维度横向对标（核心章节）
   - 5.1 核心功能模块
   - 5.2 定价、套餐、盈利模式
   - 5.3 应用场景与落地能力
   - 5.4 渠道分发与营销运营打法
   - 5.5 用户口碑、优势、痛点差评
6. 头部竞品逐家 SWOT（S/W/O/T + 核心打法与护城河）
7. 市场差异化与竞争缺口
   - 7.1 同质化问题
   - 7.2 未被满足的需求与功能缺口
   - 7.3 竞品短板与可突破切入点
8. 整体竞争风险与挑战
   - 8.1 头部压制、内卷
   - 8.2 技术迭代、政策合规、用户留存
   - 8.3 新入局者冲击
9. 未来竞争趋势预判
   - 9.1 功能迭代
   - 9.2 运营与渠道
   - 9.3 差异化方向
10. 落地策略与优化建议（核心输出）
    - 10.1 功能差异化破局
    - 10.2 市场运营突围
    - 10.3 竞品短板卡位
    - 10.4 风险规避与长期布局
11. 全文调研总结
12. 参考资料（按引用顺序或主题归类，只列正文实际引用来源；有公开 URL 附链接，无可靠链接只写名称；不堆砌、不编造）

## 3. 写作硬性要求

1. 全文以竞品对标、竞争分析为核心；绝不编造数据、观点、案例；不确定的市场数字标"待核实"或注明口径。
2. 关键数据、案例、观点标注来源类型（行业报告 / 媒体资讯 / 官方公告 / 用户调研 / 专业测评等）。
3. 多竞品横向对比优先用表格。
4. 只输出报告正文成品，不输出检索/整理过程。

## 5. 统一署名 / CTA（引流用）

每篇报告在话题标签之后，另起一行加固定署名（作为产出物的一部分，随报告一起分发）：

```
—— 本报告由 competitive-analysis-report 技能自动生成 · 更多 AI 自动化与法律科技实践，关注公众号「程序员白大力」
```

- 署名单独一行、不加粗、不与话题标签混排。
- 公众号名/链接如需更换，只改本文件这一处。

## 4. 公众号输出格式

- Markdown 文档；第一行是 `# 标题`，标题下紧接封面图。
- 除正文与话题标签外，不要多余头尾。
- 文末顺序：`## 参考资料`（第 12 节）→ 另起一行话题标签（`#标签` 形式）。
- Markdown 加粗片段 `**...**` 的开头和结尾不得紧接标点（：、。，；等），加粗两端必须是文字本身。
